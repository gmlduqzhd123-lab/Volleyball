|---|---|---|
| 영상 상세에서 돌아오면 검색 조건 소실 | 기초 영상 + 스파이크 + 수비 담당의 3개 결과가 전체 84개로 초기화. 기존 `#/pro` 주소도 상세에서 일반 목록으로 잘못 복귀 | 목록 상태와 출발 목록을 앱에서 유지. 일반 목록 및 기존 프로 주소에서 브라우저 뒤로가기와 상세의 영상 목록 링크로 복귀 검사 |
| 퀴즈 재도전 시 이전 점수가 표시됨 | 1/10 기록에서 10/10으로 갱신해도 다시 풀기 화면은 1/10 | 저장 성공 시 화면의 지난 기록도 갱신. 실제 localStorage와 재도전 화면 비교 |
| 모바일에서 다음 문제의 질문이 화면 밖으로 사라짐 | 320×568에서 질문 위치가 화면 상단 위로 밀림 | 다음 문제·결과·재도전 시 제목에 초점을 두고 화면으로 이동 |
| 상세 화면의 현재 메뉴 접근성 안내 누락 | 시각적으로는 선택되어도 aria-current 없음 | 영상 및 기술 상세의 상위 메뉴에 현재 위치 안내 추가 |
| 가로 화면 QR 상단 잘림 | QR 창을 열자마자 아래 닫기 버튼에 초점이 이동해 QR 상단이 가려짐 | 대화상자에 초기 초점, 화면 높이에 맞춘 QR 크기. 실제 화면 캡처를 디코딩해 공개 주소 확인 |
| 모바일 QR·설치 안내창의 초점 복귀 실패 | WebKit에서 터치한 버튼이 활성 요소가 아니어서 닫은 뒤 버튼으로 복귀하지 않음 | 창을 연 버튼을 명시적으로 기억하고 복귀. 초기 위치·Tab/Shift+Tab·Escape 검사 |
| 일시적 서버 오류 때 이미 저장된 학습 자료를 사용하지 못함 | HTML·기술 JSON에 HTTP 503을 주입하면 캐시가 있어도 오류 화면 | 5xx 응답 시 캐시된 정상 자료 사용. 실제 서비스 워커에 오류를 주입해 복구 검사 |

503 검사는 통제된 장애 모의 실험이며, 운영 사이트에서 실제 503 장애가 발생했다는 의미가 아니다. 캐시가 없는 최초 접속까지 오프라인으로 지원한다는 의미도 아니다.

## 검증 범위

- Windows 호스트, Node.js 24.15.0, Playwright의 Chromium 156.0.8078.4 및 WebKit 27.2. 모바일은 브라우저의 터치·화면 크기 모의 환경이다.
- 주요 화면: 홈, 배구 영상, 왕초보 배구 교실, 배구 기술 교실 및 상세, 포지션 배우기, 퀴즈, 영상 상세.
- 320·360·390·430px 세로 화면과 가로 회전, 568×320·667×375의 QR 창, 1440×900 데스크톱 화면.
- 메뉴 5개, 영상 카테고리 5개, 검색·포지션 필터, 영상 상세, 클릭 후 플레이어 생성과 자동재생 없음.
- 코트 1~9번과 역할 버튼 양방향 연결, 강조 표시, 설명, 모바일 회전과 설명 보기.
- 퀴즈 10문항·채점·저장·재도전, 저장소 거부·손상된 데이터·네트워크 실패 시 복구 안내.
- QR 이미지 디코딩·PNG 다운로드, 실제 브라우저 클립보드, 공유 데이터 전달·사용자 취소·클립보드 거부 및 설치 이벤트의 모의 검사.
- 실제 빌드의 하위 경로 직접 접속·새로고침, PWA manifest·아이콘·서비스 워커·오프라인 학습 화면.

공유 대상 앱으로 전송하거나 OS에 설치를 완료하는 작업은 하지 않았다. 공유 API 및 설치 이벤트의 모의 검사를 실제 OS 동작으로 간주하지 않는다.
